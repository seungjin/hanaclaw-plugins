# hanaclaw-plugins — agent notes

Personal plugin catalog for hanaclaw (a ZeroClaw fork). Not an application:
Rust plugin crates in `plugins/`, plus small Python tools. `README.md` is the
human-facing guide; this file is the working contract for agents.

## Layout
* `plugins/<name>/` — one WIT component per directory: `manifest.toml`,
  `Cargo.toml` + `Cargo.lock`, `src/core.rs` (pure, host-testable),
  `src/lib.rs` (wasm shim), `tests/`, and a built `.wasm` next to the
  manifest (gitignored).
* `wit/v0/` — vendored ZeroClaw plugin contract, shared by every plugin via
  `path: "../../wit/v0"`. Never hand-edit; refresh with
  `tools/fetch_zeroclaw_wit.py`. `UPSTREAM_REF` and `.sha256` are generated.
  `wit/v0/README.md` is upstream's file — it is listed in `.sha256`, so local
  commentary goes elsewhere (here, and in the root `README.md`).
* `templates/zeroclaw-tool-plugin/` — `cargo generate` template (Liquid
  syntax inside files; use `{%- ... -%}` for whitespace control).
  Placeholders: `author`, `tool_name`, `tool_description`, `registry`,
  `config_read`; each must be declared in `cargo-generate.toml` or
  substitution fails.
* `registry.json` — generated by `tools/build_plugins.py`; do not hand-edit.
* `tools/pluginpack.py` — shared packaging/validation contract (zip format,
  manifest validation, registry rendering). Change it in one place only.

## Docs map
Update the matching doc whenever behavior changes:
* `README.md` — install/build/publish flow, flag tables, recipes,
  troubleshooting.
* `AGENTS.md` (this file) — verification commands, gotchas, publishing rules.
* `templates/zeroclaw-tool-plugin/README.md` — placeholders, generated files,
  registry semantics for new crates.
* `plugins/<name>/README.md` — what the plugin does, how to rebuild and
  install it. `plugins/hello-from-hana/README.md` is the worked example.
* Tool docstrings (`tools/*.py`) — authoritative for flags; keep
  `--help` text and docs in sync.

## Verification
Run Python only through `uv` (never bare `python`/`python3`); keep
`--python 3.13` because package digests must come from stock zlib.

* `uv run --python 3.13 python tools/build_plugins.py --package` — fmt,
  test, clippy (host + wasm), wasm build, zip, registry refresh.
* `uv run --python 3.13 python tools/build_plugins.py --check` — exit 2 when
  the registry is stale.
* `uv run --python 3.13 python tools/update_zeroclaw_registry.py --check
  --offline` — upstream half only; drop `--offline` to compare against
  upstream `main` (network).
* `uv run --python 3.13 python tools/fetch_zeroclaw_wit.py --check`
  — offline WIT drift check.
* `uv run --python 3.13 python tools/publish_plugins.py --dry-run` — print
  the publish plan (no upload, no commit).
* `uv run --python 3.13 python tools/publish_plugins.py --verify-only`
  — re-download and check every local registry URL (read-only, no `gh`
  release rights needed beyond read access).
* Template changes: `cargo generate` reads the template from the git index,
  so `git add templates/` first; test all four combinations of
  `registry` x `config_read` and run the steps above on a generated plugin.
* `uvx ruff check tools/` must be clean apart from the one known `SIM115`
  in `tools/fetch_zeroclaw_wit.py` (deliberate `delete=False` temp file);
  do not add new findings.

## Publishing
* `tools/publish_plugins.py` uploads missing `dist/*.zip` assets to the
  `plugins` release (creating it if needed), rejects different bytes for an
  existing asset, verifies every local URL by download, then commits only
  `registry.json`. It does not push.
* Flags: `--dry-run` (print plan), `--verify-only` (URLs + digests only),
  `--no-commit` (upload, leave git alone), `--ref REF` (use
  `git show REF:registry.json`), `--release-tag`, `--dist`.
* Needs an authenticated `gh` (`gh auth status`) with push access, plus a
  git remote `origin`.
* Uncommitted-but-built plugins are picked up from their manifest, so a new
  plugin can be uploaded before its registry commit lands.
* Published `name@version` is immutable: bump `version` in **both**
  `manifest.toml` and `Cargo.toml` for any change that alters the wasm or the
  registry metadata (description, author, capabilities, provides,
  sender_match) — including a WIT refresh or toolchain upgrade.
* Removing a `plugins/<name>/` entry that is in the registry is an error
  unless `--prune` is passed; do that only in a deliberate commit.
* Never commit `.wasm`, `dist/`, or `target/`.

## Upstream catalog
* The upstream half of `registry.json` is inherited verbatim from
  `zeroclaw-labs/zeroclaw-plugins@main/registry.json`. Pin a refresh with
  `--upstream-ref <sha>` so the same input yields the same output.
* `registry-retirements.json` (upstream) retires identities that no longer
  install. It is not vendored: pass `--retirements <path>` to
  `build_plugins.py` / `update_zeroclaw_registry.py` to drop them.
* Only inherit upstream entries via the tools; never hand-copy entries.

## Gotchas
* Plugin `name` must be kebab-case and equal the directory name.
* `config_read` and `[config_schema]` are a biconditional; `state_read` /
  `state_write` are host-gated and need `registry = false`.
* Package zips are reproducible only under stock zlib. Use
  `uv run --python 3.13 python ...`; a system Python can link zlib-ng and
  silently produce different digests. The tools warn when they detect zlib-ng.
* cargo-generate's Liquid rejects `{% if not x %}`. Use `{% unless x %}`.
* Do not add `.cargo/config.toml` with a default wasm target to a plugin:
  `cargo test` then tries to execute the `.wasm` binary. Pass
  `--target wasm32-wasip2` explicitly (upstream CI style).
* `wit_bindgen::generate!` takes macro-rust syntax (`path: "../../wit/v0"`),
  not `path = "..."`; Rust Analyzer/rustfmt will not catch this, only the wasm
  build will. The path is relative to the plugin crate, so it breaks if a
  plugin is not exactly two levels below the repo root.
* `cargo generate` does not write `Cargo.lock`; the first build creates it and
  every other cargo command uses `--locked`.
* Never touch `~/.ssh`. No secrets in the repo.
